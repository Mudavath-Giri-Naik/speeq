### 3.3 `POST /api/v1/ingest` — validation rules (security-critical; implement exactly)

Order of checks; each failure returns a JSON body `{ "error": { "code": "<CODE>", "message": "<generic>" } }` with `cache-control: no-store`. **Never echo any part of the request body, schema issue paths or Zod messages** in a response or a log.

1. **Method:** only `POST` (others → 405 with `allow: POST`). No CORS headers, no `OPTIONS` handler (this endpoint is server-to-server; browsers must not call it).
2. **Content type:** `content-type` must start with `application/json` (case-insensitive, parameters allowed) else **415** `INVALID_INPUT`.
3. **Size cap 64 KiB, enforced while reading:** if `content-length` is present and greater than 65,536 → **413** `INVALID_INPUT` without reading. Otherwise read the stream incrementally and abort with **413** as soon as the byte count passes 65,536 (do not rely on `content-length`, and do not call `request.text()`/`json()` on an unbounded body). Missing body → 400.
4. **JSON parse:** invalid JSON → **400** `INVALID_INPUT`.
5. **Schema:** `TelemetryBatchSchema.safeParse` from `@speeq/core` (strict objects, so unknown keys are rejected). Failure → **400** `INVALID_INPUT`.
6. **Time sanity** (after the schema passes), with `now = server time`:
   - `sentAt` must be within `[now − 24 h, now + 5 min]`.
   - Each event `ts` must be ≤ `now + 5 min` and ≥ `now − 7 days`.
   - For rollups: `periodStart ≤ periodEnd`, `periodEnd ≤ now + 5 min`, `periodEnd − periodStart ≤ 7 days`.
   - Any violation → **400** `INVALID_INPUT`. (Clock skew beyond these bounds is treated as invalid; the SDK drops failed batches, so no retry storm.)
7. **Event rules:** at most one `sdk.init`, one `usage.rollup` and one `error.rollup` per batch (more → 400). Counter sanity: for a `usage.rollup`, `voiceTurns + textTurns` must equal `turns`, the sum of `languages` values must be ≤ `turns`, each histogram sum must be ≤ `turns`, and `confirmations.approved + confirmations.rejected` ≤ `confirmations.requested + turns` (a loose bound that tolerates resumes). Violations → 400. These checks stop a client from poisoning aggregates with impossible numbers.
8. **Throttle (DB-backed, atomic, serverless-safe)** — runs **after** validation so garbage cannot fill the throttle table, and before any write. Buckets: `i:<instanceId>` and `g:global`, window = the current UTC minute (`window_start` truncated to the minute). Atomic `INSERT … ON CONFLICT (bucket, window_start) DO UPDATE SET count = ingest_throttle.count + 1 RETURNING count`. Limits per window: **10** per instance, **1200** global. Exceeded → **429** `RATE_LIMITED` with `retry-after` (seconds until the next minute). Both buckets are incremented in the same statement/transaction as the check. A DB failure while throttling → fail **closed** with 503, never accept unthrottled writes.
9. **Project attribution without a key oracle:** if `projectKey` is present, look it up (`findActiveProjectByKey`). Known and active → rows get that `project_id`. Unknown or revoked → accept the batch **unattributed** (`project_id = null`) and return the **same** 202 body. The response must not reveal whether a key is valid. (A later `instances.project_id` is set once and not changed by a different key: first valid attribution wins; do not overwrite a non-null `project_id`.)
10. **Persist in one transaction:** upsert `instances` (set `first_seen` only on insert; always `last_seen = now`); if the batch has `sdk.init`, update the `sdk_version` (from `sdkVersions["@speeq/server"]`, else the first entry, else null), runtime, framework, features; insert `usage_rollups` and one `error_counts` row per `(code, count)` with `count > 0`. All-or-nothing. `received_at` is always server time.
11. **Success:** **202** `{ "ok": true }`. Same body whether or not the key was attributed.
12. **Unexpected errors** (DB down, `ConfigError`, anything else): **503** `{ error: { code: "INTERNAL", message: "…" } }` with a generic message; log one line `ingest failed` plus the error **class name only** (never message, stack, URL, body).

### 3.4 `GET /api/cron/cleanup`

- Requires header `authorization: Bearer <CRON_SECRET>`, compared in constant time (`crypto.timingSafeEqual` on equal-length digests; hash both sides with SHA-256 first). `CRON_SECRET` unset/empty → **503** (route disabled; it must never be open). Wrong/missing token → **401**. Only `GET` (and `POST` for manual runs) allowed.
- Deletes: `usage_rollups` and `error_counts` with `received_at` older than `TELEMETRY_RETENTION_DAYS` (default **90**, integer 1–3650; invalid → default); `ingest_throttle` rows with `window_start` older than 1 hour; `instances` with `last_seen` older than the retention window (cascade removes their rollups). Returns `{ ok: true, deleted: { rollups, errors, throttle, instances } }`.
- Add `vercel.json` with a daily cron (`"/api/cron/cleanup"`, `"0 3 * * *"`).

## 7. Tests required (`apps/platform/test/*.test.ts`, vitest node env, PGlite in memory, call `handleIngest` / route functions directly)

Validation (pure + handler):

- Valid batch with `sdk.init` + `usage.rollup` + `error.rollup` → 202; rows exist with correct values; `received_at` is server time.
- Wrong method → 405 `allow: POST`; wrong content-type → 415; missing body → 400; invalid JSON → 400.
- Body exactly 65,536 bytes passes the size gate; 65,537 → 413; 413 when `content-length` lies small but the stream is large; 413 from a large declared `content-length` without reading the stream.
- Unknown key in batch/event/counters → 400 (strict); `schemaVersion: 2` → 400; 51 events → 400; empty events → 400.
- `sentAt` 25 h old → 400; 6 min in the future → 400; `ts` 8 days old → 400; `periodStart > periodEnd` → 400; period of 8 days → 400.
- Two `usage.rollup` events in one batch → 400; `voiceTurns + textTurns ≠ turns` → 400; language sum > turns → 400; histogram sum > turns → 400.
- Error responses never contain any request-body substring (use a canary string inside an invalid field) and never contain Zod text such as "Expected" or "Invalid input".

Attribution:

- Known key → rows carry `project_id`; unknown key → 202 with `project_id` null and a body byte-identical to the known-key response; revoked key behaves like unknown.
- A second batch with another valid key does not overwrite the instance's existing `project_id`.
- `sdk.init` fills instance fields; a later batch without `sdk.init` does not blank them; `first_seen` unchanged, `last_seen` advances.

Atomicity / throttle:

- A failure while inserting `error_counts` (simulate by a failing dependency or invalid FK) rolls back the whole batch (no partial rows).
- 11th request in the same minute for one instance → 429 with `retry-after`; a different instance still passes; 1201st global request → 429; 20 parallel requests for one instance yield exactly 10 × 202 and 10 × 429.
- Invalid batches do not consume throttle budget (assert counts after 50 invalid requests).
- DB failure during throttle → 503 and nothing written (fail closed).

Cron:

- `CRON_SECRET` unset → 503; no/wrong token → 401; right token → 200 with counts; token comparison does not throw on different lengths.
- Rows older than retention are deleted, newer kept; invalid `TELEMETRY_RETENTION_DAYS` falls back to 90; old throttle rows removed; stale instances removed with cascade.

DB client / config:

- `DATABASE_URL=https://x.supabase.co` → `ConfigError` with a message that does not contain the URL; the ingest route returns generic 503.
- Migrations apply cleanly on a fresh PGlite and are idempotent on re-run.

## Amendment A (architect decision, answers the blocked report)

Rule 7 is wrong for confirmations: an approval or rejection can arrive in a later batch than its
request, because the collector resets counters after each send and a resume is not a turn
(Task 006 Amendment A). **Remove the confirmations inequality entirely** from §3.3 rule 7; the
confirmation counters get no cross-field check beyond the schema's own per-counter limits.

Rule 7 keeps these checks, which hold within a single batch by construction because they are all
incremented together in `turn()`: `voiceTurns + textTurns = turns`; sum of `languages` values
≤ `turns`; each latency histogram sum ≤ `turns`. Do not add any other cross-field or cross-batch
check, and do not reject batches on a rule you cannot prove the real collector always satisfies.

Update the validation tests accordingly: delete the confirmation-inequality case and add one
asserting that a rollup with `approved: 1, requested: 0, turns: 0` is accepted (202). Add one
integration test that sends the real SDK's two batches from a bookmark request followed by an
approval (`flushIntervalMs: 0`) and expects 202 for both.
